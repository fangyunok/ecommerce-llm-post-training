# 实验006：自然语言约束抽取

## 目标

实验005需要人工提供结构化JSON。实验006补齐第一段链路，将受支持的中文商品比较文本转换为商品字段、硬约束和排序目标，再交给确定性规则引擎：

`自然语言 → 结构化抽取 → 硬约束过滤 → 排序 → 可审计答案`

## 第一版实现

抽取器目前支持：

- 数值与单位：元、mAh、GB、TB、kg、英寸、Hz、MP、小时；
- 约束：预算上限、至少、不低于、不超过；
- 排序：价格最低、续航最长、像素最高；
- 商品形式：A/B/C款、字母加商品名、甲/乙/丙及部分常用组合；
- 无法稳定识别至少两个商品时返回HTTP 422，不静默猜测。

新增端点：`POST /v1/natural-language-recommendations`。响应同时返回`extracted`结构和`recommendation`结果，便于排查是抽取错误还是决策错误。

## 分层评测

| 数据集 | 题数 | 结构完全一致 | 最终决策正确 |
|---|---:|---:|---:|
| 原数值题 | 11 | 11/11 | 11/11 |
| 独立改写题 | 5 | 5/5 | 5/5 |
| 合计 | 16 | 16/16 | 16/16 |

“结构完全一致”同时比较商品名称与字段绑定、数值、约束运算符、阈值、排序字段和方向。改写题使用不同数值及“最多花”“价格上限”“不低于”“不高于”“续航最久”等表达，避免只复测原句。

## 复现

```powershell
python -m unittest discover -s tests -v
python scripts\evaluate_extraction.py
python scripts\evaluate_hybrid.py
```

全部过程在CPU上完成，不需要租用GPU。

## 局限性

当前16/16只代表受支持表达范围内的精确结果，不能解释为开放域自然语言100%准确。第一版是确定性词典和正则抽取器，仍不支持自由商品名称、复杂指代、单位换算、多轮补充条件和任意语序。

下一阶段应扩大人工改写测试集并加入失败样本，然后评估两种路线：受JSON Schema约束的大模型抽取，或规则优先、大模型回退。无论采用哪种路线，都应继续分别报告抽取准确率、规则决策准确率和端到端准确率。
