# 实验005：结构化规则与大模型协同

## 问题

实验004的1.5B SFT模型总体达到24/40（60.0%），但数值筛选仅1/11。错误集中在预算边界、阈值比较、先过滤后排序以及数值与商品绑定。此类操作需要确定性计算，不适合完全依赖语言模型概率生成。

## 系统设计

第一版采用两条决策路径：

1. 摘要、信息不足判断等语言任务继续使用1.5B SFT模型；
2. 数值筛选任务将结构化商品JSON交给规则引擎；
3. 规则引擎先执行全部硬约束，再只对合格商品排序；
4. 返回选中商品、合格候选列表、推荐理由和`deterministic_rules`来源标记。

新增接口为`POST /v1/rule-recommendations`。请求显式包含商品字段、`le/lt/ge/gt/eq`约束、升降序目标和需要展示的事实字段，因此每一步都可以审计和复现。

## 评测结果

| 系统 | 总体 | 数值筛选 |
|---|---:|---:|
| 1.5B基座 | 18/40（45.0%） | 6/11（54.5%） |
| 1.5B + SFT | 24/40（60.0%） | 1/11（9.1%） |
| 1.5B + SFT + 规则路由 | 34/40（85.0%） | 11/11（100%） |

混合系统保持原模型在其余29题上的答案不变，仅替换11道数值筛选题的决策结果，因此总体从24题提升到34题。

## 如何复现

```powershell
python -m unittest discover -s tests -v
python scripts\evaluate_hybrid.py
```

规则用例位于`data/eval/ecommerce_rules_eval.jsonl`，混合结果保存于`outputs/evaluation/hybrid_rules_v1_extended.jsonl`及对应summary文件。

## 结果边界

85.0%是“结构化输入已正确提供”条件下的离线编排结果，不是任意自然语言输入的端到端准确率。目前尚未解决：

- 如何从用户自然语言稳定提取商品、单位、约束和排序目标；
- 同义字段和单位换算，例如克与千克、GB与TB；
- 多级排序、并列结果和字段缺失时的业务策略；
- 规则结果如何交给模型润色且不被模型篡改。

下一阶段应增加受JSON Schema约束的信息抽取器，并分别评测“字段抽取准确率”“规则决策准确率”和“最终回答准确率”，避免只报告一个混合总分。
